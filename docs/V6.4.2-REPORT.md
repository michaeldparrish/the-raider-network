# v6.4.2: Autosave indicator and the Trade Board hand-off

This is an incremental patch on top of v6.4.1 (`e83dfcb` on your Mac, `16b2ae3` here; both have the same tree `732d2f0a…`).
- No migrations.
- No server or API changes.
- No D1 changes.

## What changed

**1. Autosave indicator** (`assets/js/trails.js`, `assets/v5.css`)
- The indicator is right-aligned on the "N MATERIALS · x of y gathered" heading, above the progress bar.
- States:
  - "Changes save automatically" (idle)
  - "Saving…" while the request is in flight
  - a green check with "Progress Auto Saved", shown only after the server confirms
- On a network error, 5xx, 408 or 429, it shows "Save failed — retry" (`role="alert"`). Retry resends the same change.
- The +/- buttons now send an absolute collected count, so a retry can't double-count.
- When the server refuses a change (4xx, e.g. an invalid install), it shows the server's message and reverts to the saved state.
- There is no Save button.

**2. "Archive plan" is replaced by "Find Missing Items on Trade Board"**
- The button opens a "Missing materials" panel. It lists every material the server reports as still outstanding or with an unknown quantity, each with "Need N".
  - N is the plan's calculated outstanding quantity, capped at 99, the Trade Board maximum.
  - Conflicting quantities are flagged "check in game".
  - Items that aren't in the catalog (`label:` parts) are listed but can't be selected.
- You can select one material or several, or use Select all / Select none.
- "Create Trade Request" (or "Create N Trade Requests") opens the Trade Board with a review form already filled in.
  - Nothing is posted at this point.
  - Region, platform and note are prefilled.
  - Unknown quantities must be entered by hand.
  - Disputed or unverified quantities show a warning.
- "Post Request" (or "Post N Requests") creates one normal Trade Board request per material.
  - It uses the existing `createTrade` path, so the same sign-in, CSRF protection, rate limit and validation apply.
- Duplicates are blocked: if you already have an open request for a material, that row is disabled with a "View it" link. This is checked again just before each post.
- Hand-off links are cleaned before use:
  - only catalog items are kept;
  - quantities are clamped to 1–99;
  - only known status values are kept;
  - the list is capped at 30 items.
- If you're logged out, you're sent to sign in and then returned to the same review.
- Plan collected counts are never changed by posting.
- Archived plans, the ARCHIVED status and the status API are unchanged. The button is simply gone from the card.
